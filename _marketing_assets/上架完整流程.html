阶段 1　修正 5 处工程配置

这 5 处我已经帮你逐项定位好了。改法在下面，也可以让我直接改（见文末）。

1.1 只支持 iPhone（去掉 iPad）

为什么：TARGETED_DEVICE_FAMILY = "1,2" 表示 iPhone + iPad。一旦声明支持 iPad，App Store 会强制要求上传 13 英寸 iPad 截图，而你的游戏是竖屏，在 iPad 上就是一块被拉大的手机画面，本来也不该支持。

改法：

Xcode 左侧点蓝色 App 工程 → TARGETS 下的 App
  → General 标签
  → 找到 "Supported Destinations"
  → 只保留 iPhone，选中 iPad 点 - 删掉

1.2 锁定竖屏

为什么：Info.plist 现在声明支持竖屏 + 左横 + 右横。游戏是竖屏布局，审核员一转手机就会看到错位破版，容易触发 2.1（崩溃/界面异常）。

改法：

TARGETS → App → General → Deployment Info
  → Device Orientation
  → 只勾 Portrait，取消勾选 Landscape Left / Landscape Right

1.3 删掉过时的 armv7 声明

为什么：Info.plist 里有 UIRequiredDeviceCapabilities = [armv7]，这是 32 位时代的老写法。现在 App Store 只接受 64 位，这个声明会让 App 被判定为不支持现代设备。

改法：Info.plist 里找到 Required device capabilities，把 armv7 这一项整行删掉（键可以整条删除）。

1.4 加出口合规声明（省掉每次上传被追问）

为什么：每次上传完，App Store Connect 都会挂一个「缺少合规信息」的黄色提示，要你单独回答加密问题。提前写进 Info.plist 就不用管了。

改法：Info.plist 添加一个布尔项：

Key:   ITSAppUsesNonExemptEncryption
Type:  Boolean
Value: NO

依据：你的游戏完全离线、不发起网络请求、不使用自定义加密算法。仅依赖系统自带的 HTTPS 属于豁免范围。

1.5 Privacy Manifest（先不做，看邮件决定）

背景：Apple 自 2024-05-01 起要求声明「Required Reason API」的使用原因。你工程里没有 PrivacyInfo.xcprivacy。

做法：先按流程上传。上传后 30 分钟内检查开发者邮箱：

  • 收到标题含 **`ITMS-91053: Missing API declaration`** 的邮件 → 按附录 C 补一个文件再重新上传
  • 没收到 → 说明你的依赖没触发，不用管

  • 用手机打开 App Store 链接确认图标、截图、描述都正常
  • 装一遍真机版本，确认首次启动有声、存档正常

阶段 8　被拒了怎么办

8.1 常见拒绝代码（针对你这个项目）

代码含义为什么会撞上怎么改
2.1App 崩溃或有明显 bug存档结构不兼容、横屏破版修好后重新上传 build，回复审核员说明已修
2.3.1隐藏功能 / 描述与实际不符文案写了游戏里没有的东西改文案或改游戏，二选一
2.2占位内容、不完整隐藏的内购入口、空页面确保 MONETIZATION_ENABLED = false 已生效
3.1.1站外解锁付费内容假广告按钮、「去广告」入口已通过门控隐藏，重点是别让审核员看到
4.2最低功能要求 / 太简单单机小游戏被判套壳强调关卡数量、机关种类、图鉴与成就系统
5.1.1隐私政策问题网址打不开、信息不全部署可访问的页面，写清联系邮箱
2.3.8截图不合规截图里有不当内容你的截图没问题

8.2 回复模板

不要重新提交整个版本，先在 App Store Connect → 审核 → 被拒信息 下方直接回复：

Hello,

Thank you for the review. Regarding guideline X.X.X:

(用一两句说清楚你做了什么修改，例如：
 We have removed the hidden in-app purchase entry points entirely.
 The new build 2 no longer contains any disabled or placeholder button.)

We have uploaded a new build (1.0 build 2) for review. Please let us know
if anything else is needed.

Best regards,
<你的名字>
Potion Sort

要点：逐条对应、只讲改了什么、不要说「这是误会」。态度平和、事实清楚，二次过审概率很高。

阶段 9　以后怎么更新版本

简化版，每次发新版本重复这几步：

  1. `git pull` → 改代码 → `npx cap sync ios`
  2. Xcode 里把 **Version** 改成 `1.1`（功能更新）或 `1.0.1`（修 bug），**Build 号继续往上加**
  3. Archive → Distribute → Upload
  4. App Store Connect 新建版本记录，填「此版本的新增内容」
  5. 上传新截图（只有界面变了才需要）
  6. 提交审核

只改文案不改代码，可以在 App Store Connect 里直接改，不需要重新上传包（但要走一次元数据审核）。

附录 B　中国大陆区与版号（必须做决定）

Apple 官方帮助明确写着：

游戏 App 必须取得网络游戏出版物号（版号 / ISBN）。为方便 Apple 验证，需上传 ISBN 核发单或批复文件，以及最新营业执照副本。

现实情况：

项说明
谁能申请必须通过持有网络出版资质的中国出版单位提交，个人开发者不能自己申请
周期通常 6~12 个月，且不保证获批
费用通过代理办理通常数万元起
额外要求部分 App 还需 ICP 备案号，且备案信息要与 App 信息一致

结论与建议：

  • 首发**不要**选中国大陆区，在「定价与销售范围」里取消它，其他 174 个地区正常上架
  • 等有了版号，再回 App Store Connect 勾上中国大陆、填 ISBN，不需要重新提交版本
  • 简体中文语言仍然可以保留（给海外华人用户用），只是不在中国大陆区销售

如果你的目标是先跑通上架流程、拿到一个真实上线的 App，这是唯一可行路径。硬要闯中国区，结果是被卡在提交环节，一步都动不了。

附录 C　Privacy Manifest（收到 ITMS-91053 才做）

在 ios/App/App/ 下新建文件 PrivacyInfo.xcprivacy，内容：

<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
	<key>NSPrivacyTracking</key>
	<false/>
	<key>NSPrivacyTrackingDomains</key>
	<array/>
	<key>NSPrivacyCollectedDataTypes</key>
	<array/>
	<key>NSPrivacyAccessedAPITypes</key>
	<array>
		<dict>
			<key>NSPrivacyAccessedAPIType</key>
			<string>NSPrivacyAccessedAPICategoryUserDefaults</string>
			<key>NSPrivacyAccessedAPITypeReasons</key>
			<array>
				<string>CA92.1</string>
			</array>
		</dict>
	</array>
</dict>
</plist>

然后在 Xcode 里：

右键 App 文件夹 → Add Files to "App" → 选中 PrivacyInfo.xcprivacy
→ 确认勾选了 App target → Add

最后重新 Archive 上传。CA92.1 的含义是「仅访问本 App 自己的偏好设置」，符合你的情况。
